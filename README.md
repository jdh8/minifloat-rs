# minifloat

[![Build Status](https://github.com/jdh8/minifloat-rs/actions/workflows/rust.yml/badge.svg)](https://github.com/jdh8/minifloat-rs)
[![Crates.io](https://img.shields.io/crates/v/minifloat.svg)](https://crates.io/crates/minifloat)
[![Documentation](https://docs.rs/minifloat/badge.svg)](https://docs.rs/minifloat)

Rust meta-library for minifloats — emulate floating-point types with fewer
bits than the built-in `f32` / `f64`, configurable along every axis.

## Quick start

```rust
use minifloat::{minifloat, impl_from_minifloat_for_f32, impl_from_minifloat_for_f64, Minifloat};

minifloat!(pub struct E4M3FN(u8): 4, 3, FN);
impl_from_minifloat_for_f32!(E4M3FN);
impl_from_minifloat_for_f64!(E4M3FN);

let x = E4M3FN::from_f32(1.5);
let y: f32 = x.into();        // lossless round-trip
assert_eq!(y, 1.5);

assert!(E4M3FN::NAN.is_nan());
assert_eq!(E4M3FN::MAX.to_f32(), 448.0);
```

## Configuration axes

A minifloat is generated by the [`minifloat!`] macro from these parameters:

- **Exponent width** — number of exponent bits, must be ≥ 2
- **Significand precision** — explicit mantissa bits (excluding the implicit
  leading bit)
- **Exponent bias** — defaults to 2<sup>E&minus;1</sup> &minus; 1 (IEEE
  convention)
- **NaN encoding style** — one of:
  - `IEEE` &mdash; standard, has both ±∞ and NaN
  - `FN` &mdash; finite-only with a special NaN encoding (no infinities)
  - `FNUZ` &mdash; finite-only NaN, unsigned zero (no infinities, no &minus;0)

The total bit-width must be < 17 (16 magnitude bits plus a sign).

## Predefined types

| Type   | Bits | E | M | NaN style | Notes                  |
| ------ | ---- | - | - | --------- | ---------------------- |
| `F16`  | 16   | 5 | 10 | IEEE     | IEEE 754 half-precision|
| `BF16` | 16   | 8 | 7  | IEEE     | Brain Float 16         |

The [`example`] module additionally provides several 8-, 6-, and 4-bit types
(`F8E4M3FN`, `F8E5M2`, `F4E2M1FN`, &hellip;) used in machine-learning workloads.

## Design philosophy

- **Lossless conversions are idiomatic, lossy ones are explicit.**  Each
  generated type exposes `HAS_EXACT_F32_CONVERSION` / `HAS_EXACT_F64_CONVERSION`
  compile-time constants.  When `true`, you can opt into `f32::from(x)` /
  `f64::from(x)` via the [`impl_from_minifloat_for_f32!`] /
  [`impl_from_minifloat_for_f64!`] helpers; both predefined types and every
  type in [`example`] already opt in.  Lossy conversions stay method-only:
  `from_f32`, `from_f64`, and the always-available `to_f32` / `to_f64`.

- **Bit-exact storage is the public contract.**  All representations are
  inspected via `to_bits` / `from_bits`.  NaN sign bits are preserved through
  conversions where the encoding allows.

- **No `num_traits::Float`.**  `FN` and `FNUZ` lack infinities; `FNUZ` lacks
  &minus;0.  The crate exposes its own [`Minifloat`] trait instead.

## Arithmetic

Binary `+`, `-`, `*`, `/` and their compound forms are implemented for every
generated type.  Addition/subtraction/multiplication route through `f32` when
the type's precision and exponent range allow it (`USE_F32_ADD`,
`USE_F32_MUL` are exposed as `pub const` items), falling back to `f64`
otherwise.  Division always routes through `f64`.

```rust
use minifloat::F16;
let x = F16::from_f32(1.5);
let y = F16::from_f32(2.5);
assert_eq!((x + y).to_f32(), 4.0);
```

## Hashing

All generated types implement [`Hash`](core::hash::Hash) with `+0` and
`&minus;0` normalized to the same hash (matching their `PartialEq`).  Like
`f32` / `f64`, minifloats do not implement `Eq` because `NaN != NaN`, so
direct use as `HashMap` keys requires a wrapper.
